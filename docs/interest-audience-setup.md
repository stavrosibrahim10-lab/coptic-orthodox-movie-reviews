# Newsletter interest and audience analytics
1. In Netlify environment variables set NEWSLETTER_MODE=off and leave NEWSLETTER_LAUNCH_ENABLED unset (or false). The deployed code also gates the original DOI and monthly campaign handlers behind the latter switch. No Brevo or OpenAI calls occur from the interest path.
2. Before merging, open the Supabase SQL Editor and run `supabase/migrations/20261127_interest_audience.sql` in full. It preserves old event records, creates the private interest table, extends event types and updates the aggregate RPC. Do not expose newsletter_interest through public APIs.
3. Deploy, open the site and register a test address twice (including mixed case), verify one row in Supabase Table Editor > newsletter_interest and no Brevo/OpenAI activity. Test consent, invalid email and error responses. Remove the test address afterward. Existing Brevo subscribers remain untouched; this new list is separate and unverified.
4. Open /studio/ > Analytics while logged in. Use the 7/30/90 day filters. Test home, browse, movie, search, share, opt-out and repeat browser visits. New metrics only start after deploy; legacy movie/search records are retained.
5. The browser ID rotates after 30 days. To limit server-side identifier retention, periodically execute: `update public.studio_events set visitor_id=null,session_id=null where created_at<now()-interval '90 days' and (visitor_id is not null or session_id is not null);` This preserves historical event totals. No automatic database retention job is installed.
6. When the newsletter is ready, review applicable consent/verification requirements and opt-out handling; do not automatically import unverified interest emails. Re-enable sending only after a deliberate launch decision and tested confirmation flow.
